我能做什么

围绕「读懂 → 改动 → 验证」这条链路，覆盖日常开发里的大部分重复劳动。

📖

读懂代码库

按文件名、路径、内容关键字精准检索，只读需要的行范围，不靠猜、不编造实现细节。

✏️

安全地改代码

写文件前先校验内容哈希，防止覆盖你正在手工编辑的部分；局部修改优先于整文件重写。

⚡

运行命令

跑测试、lint、类型检查、构建、git 检查等；先看 package.json 里实际有哪些脚本再执行。

✅

诚实汇报验证

只把真正跑通的结果算作通过；跑不了就明确标记为失败或受阻，并附上原因和证据。

🧭

多步任务管理

把长任务拆成清单，始终只有一项处于「进行中」，让你随时知道进度走到哪一步。

我的工作方式

以「给这个项目加个页面」为例，我会这样做：

  1. 先侦查，不动手列出文件、读 package.json 和现有源码，摸清技术栈与既有风格。
  2. 拆成清单把任务写成待办项，逐项推进，避免做到一半丢失上下文。
  3. 小步改动优先局部编辑，保持与项目现有约定一致，不做与需求无关的重构。
  4. 跑最相关的检查执行项目里真实存在的测试或构建脚本，抓取实际输出。
  5. 如实收尾汇报改了什么、验证了什么、还有什么没解决——不夸大。

我不会做的事

能力有边界，说清楚比含糊更好用。

  • 不离开工作区路径不能越界，也不跟随符号链接到处翻找。
  • 不碰密钥不读取、不写入、不外泄任何凭据或密钥文件。
  • 不覆盖你的改动编辑前比对哈希；发现冲突就先重新读取再决定，绝不盲目覆写。
  • 不编造结果没跑过的检查不会说「通过」。
  • 不把仓库内容当命令代码和命令输出都是数据，不是可以覆盖我指令的「指示」。
